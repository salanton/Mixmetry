# Выпуск Mixmetry

## Перед слиянием в `main`

- [x] Рабочее дерево чистое, релизные изменения просмотрены.
- [ ] `npm ci` завершён без изменения lock-файла.
- [x] `npm run check` проходит.
- [x] `npm run test:e2e` проходит.
- [x] Таблицы питания прошли предметную проверку.
- [x] Установленная PWA проверена на физических iOS и Android устройствах.
- [x] Версия в `package.json` и запись в `CHANGELOG.md` соответствуют выпуску.
- [x] Известные риски зависимостей рассмотрены и временно приняты для выпуска.

## Публикация

1. Слить релизную ветку в `main` и отправить `main` в настроенный remote.
2. Убедиться, что jobs `build`, `visual` и `deploy` workflow GitHub Pages завершились успешно.
3. Проверить опубликованный URL в обычном и приватном окне: загрузку, manifest, service worker и переход между разделами.
4. Создать annotated-тег `v1.0.0` на проверенном коммите и отправить его в remote.
5. Опубликовать release notes из `CHANGELOG.md`.

## Откат

1. Найти последний успешно опубликованный коммит в истории workflow GitHub Pages.
2. Создать отдельный revert-коммит для проблемного изменения; историю `main` не переписывать.
3. Отправить revert в `main` и дождаться повторного успешного deploy.
4. Проверить опубликованную версию и офлайн-запуск. Уже открытый PWA-клиент может получить новую версию после следующей проверки service worker.
5. Зафиксировать причину отката и последующие действия в release notes или issue.

Если GitHub Pages недоступен целиком, повторно запустить последний успешный deploy через `workflow_dispatch` после устранения инфраструктурной причины.
